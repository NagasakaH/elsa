# Elsa実行環境要求

現在の状態の概要
- ElsaServerがElsaWorkflowとElsaStudioを起動しワークフローと管理用のウェブUIを操作可能にする
  - MassTransit関連の拡張をExternal配下に作成(ElsaExtensionsから複製して改変)
- 使用しているライブラリの元のソースコードはsubmodules/配下に配置してあるので必要に応じて参照する

既存のソースコードと要求を元に下記の作業を進めて欲しい

- 要件定義書の作成
- 基本設計書の作成
- 要件・基本設計に対するテスト設計書の作成
- 既存のプロジェクトからの修正計画の作成
  - 備考
		- 期間等の情報は不要
		- 実施する必要があるタスクと依存関係のみを整理する
		- 修正計画を実行するためのエージェントを./github/agents/implementation.agent.mdに作成する
		  - 可能な限り会話の回数を減らし、subagentなどを駆使して一度に作業を進めること
		  - plans/配下でタスクの実行状況を管理する
			  - plan.mdに全体の作業計画
				- progress.mdに作業計画の進捗状況に関する記録を追記していく
			  - plans/note配下に作業途中で決定した事項や調査結果などの重要な情報をｍｄファイルとして作成して記録する
			- 実装は下記の順番を遵守して実施すること
				- 詳細設計書の作成
				- 単体テストの作成
				- 実装
				- テスト
  - 実装


要求

- MassTransitのメッセージでTaskIdとRunTaskIdを指定してワークフローを実行する
	- TaskIdとワークフローは1対1で対応する
	- TaskIdとワークフローの紐づけはシステム側で管理する
	- RunTaskIdはで管理する番号でワークフローを実行するインスタンスと対応する
	- RunTaskIdとインスタンスの紐づけはシステム側で管理する
	- ワークフローはJSONで管理する
	  - システム起動時にワークフローを読み込む
		- ワークフローのJSONを作成するためのルールを整備する
		  - ワークフローに関するルールはdocs/workflows/rules.mdに記述する
			- ワークフローの設計資料はdocs/activities/<ワークフロー名>.workflow.mdとして作成すること
				- workflow-<TaskId>.jsonとしてTaskIdとファイル名で紐づけて管理する
				- すべてのワークフローはMassTransitにメッセージをPublishするアクティビティを使ってタスクの実行状態(RunTaskIdとStatus)を外部に通知する
				  - Running,Suspended,Finished,Error
			- ワークフローのjsonを生成AIで作成するためのagentファイルをAGENTS.md形式で.github/agents/workflowdesign.agent.mdとして作成する
			  - workflowの仕様のドキュメントを作成する
				  - workflow内で使用するアクティビティはdocs/activitiesにあるもののみを使用可能
				- ドキュメントに記述した内容に対するテストを作成する
- ワークフローで使用するカスタムアクティビティはActivitis/配下のDLLをロードしたものを使用することができる
	- カスタムアクティビティを生成AIで作成するためのagentファイルをAGENTS.md形式で.github/agents/activities.agent.mdとして作成する
	  - アクティビティ作成/テスト用のテンプレートプロジェクトを準備する
		  - アクティビティのdllが出力できること
		- アクティビティはテンプレートプロジェクトを複製して作成する
		- アクティビティのテストを作成すること
		  - Elsaにアクティビティとしてロードできること
			- Inputに対して期待通りのOutputが出力されること
			- Inputに対して期待通りの動作をすること
  - アクティビティの作成に関するルールはdocs/activities/rules.mdに記述する
		- アクティビティには内部エラーが想定される場合はエラーに対応するOutcomesを設定すること
		- アクティビティの設計資料はdocs/activities/<アクティビティ名>.activitie.mdとして作成すること
  - ActivitiesはMassTransitのメッセージの定義から作成することができる
		- Publish(送信)を行うアクティビティ
		- Subscribe(受信待ち)を行うアクティビティ
	- MassTransitの定義以外でも任意のActivitieを作成することができる
